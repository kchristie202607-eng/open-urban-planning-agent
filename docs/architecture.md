# 片区策划知识库与 Agent 系统架构

## 1. 目标

系统面向城市更新片区策划，将非结构化政策与规划资料转化为可检索证据，并将证据、人工确认约束和项目输入组合成可复算成果。核心不是“自动写一份报告”，而是建立从来源到结论的证据链。

## 2. 三库三层

### 库 A：编制规范与方法论

内容包括城市更新专项规划、片区策划、项目实施方案、片区体检、成果形式、实施评估和档案移交等。

### 库 B：地方实操与指标参数

内容包括贵州地方更新任务、片区与项目分类、历史文化、完整社区、产业活化、项目实施与资金机制等。

### 库 C：成果生产与质量规范

内容包括卫片与 GIS 等比例制图、图件来源优先级、网络照片证据分级、缺失图纸预留任务书、文档渲染与结构质检等。库 C 是内部工作规范，不得冒充政策或法定规划要求。

### 三层数据

1. 原文证据层：逐页文本、文件状态、PDF 页码、抽取方式和置信度。
2. 结构化候选层：规则类别、指标词、数字表达式、强制等级候选和复核状态。
3. 检索应用层：面向问题的检索块、排序、来源过滤与结果引用。

## 3. 约束闸门

任何进入数值计算的指标都必须属于以下两类之一：

- `verified_constraint`：已由人工核验来源、效力、适用范围和单位；
- `model_assumption`：为方案比较显式设置，并在成果中持续标识。

检索到的文字默认不能直接进入计算。征求意见稿、案例、OCR 低置信度内容、适用范围不明内容和来源冲突内容必须进入待复核清单。

## 4. Agent 协作

### 总控策划 Agent

负责拆解任务、调用其他角色、组织情景方案和汇总成果。它不直接绕过约束闸门。

### 证据检索 Agent

负责库 A、库 B 分库检索，输出来源文件、页码、原文、抽取方式、置信度与文件状态。

### 约束审查 Agent

将信息分类为已复核约束、引导性指引、案例参考、模型假设、冲突和待复核项。

### 空间与指标 Agent

执行用地、容积率、建筑面积、基底、层数、高度、绿地、公共空间、停车与业态分配计算，并生成体块 GeoJSON。

### 财务与项目库 Agent

执行建安、存量改造、公共空间、其他费用、预备费、收益和资金缺口测算，形成近期、重点和储备项目。

### 成果质检 Agent

检查配比、总量、上限、跨成果一致性、证据完整性和人工复核事项。

### 技术总工 Agent

位于最终交付闸门。先锁定项目行政区、类型、规模、阶段和成果范围，再核验现行国家、省、市县标准规范导则、法定规划和合同任务书的效力与适用性；综合各专业成果、约束审查和质量报告，输出分级、可定位、可整改、可复核的 `technical_review.json`。存在未关闭的 `A_blocker` 时不得交付。技术总工审查不替代法定审批、专项审查或注册专业人员签章。

### 图件与照片证据 Agent

组织各体检小节的图件任务，优先复用正式图纸和现有 GIS 数据；对卫片执行统一投影与比例误差校核；对网络照片核查对象、城市、来源和日期；对缺失图件生成制图任务预留图框。

### 规划分析图制图 Agent

负责规划分析图的数据源路由、图纸配准、逐点矢量化、拓扑检查、专题符号、图号图名、可编辑PPT与局部渲染质检。优先采用法定规划数据库、测绘、GDB、CAD和规划道路中心线；JPG、PNG、PDF与PSD只有在完成控制点配准并记录残差后方可进入正式矢量化。

### 片区调查第二章专用角色组

第二章采用片区调查总控、现状条件、片区体检评估、资源与权属、意愿调查、规划分析图制图、第二章装配和成果质检角色。总控角色锁定唯一主稿，按2.1现状概况、2.2问题调查、2.3资源调查、2.4意愿调查依次推进；证据来源、统计口径和复核状态留在内部层，正文只表达现状、问题、判断和更新响应。

角色配置见 `config/area_survey_agents.json`，阶段与闸门见 `config/area_survey_workflow.json`，项目状态见 `project_state/`。

## 5. 图件生产与证据分级

图件按以下四类记录：

1. `official_drawing`：已有正式图纸，保留名称、版本、日期和来源。
2. `gis_generated` / `satellite_gis`：基于现有 GIS 数据生成，记录图层、坐标系、显示投影和比例校核。
3. `network_photo_clue`：网络照片线索，记录对象、页面、网址、检索日期并要求现场复核。
4. `placeholder_brief`：资料不足时的制图任务预留图，记录所需数据、建议比例尺和表达要求。

卫片制图先在 Web Mercator 中按成图宽高比扩展视口，再统一映射影像和矢量。质量闸门要求：

```text
相对比例误差 =
  abs(投影视口宽高比 / 成图画布宽高比 - 1)

相对比例误差 <= 1e-6
```

禁止对卫片、GIS 边界或区位小插图进行横向或纵向单独拉伸。

新绘或重绘图件还必须生成 `map_manifest.json`，逐图记录图号、图名、正文小节、来源图层、源与显示坐标系、画布、投影视口、输出文件和质量检查状态。问题图只突出问题对象；更新潜力图采用限制面网格与存量点位；生态资源图表达河流、水体、体育公园及上位规划绿地；道路交通图另交单页可编辑PPTX。

## 6. 计算模型

主要公式：

```text
总建筑面积 = 总用地面积 × 目标容积率
建筑基底上限 = 总用地面积 × 建筑密度上限
平均层数 = 向上取整(总建筑面积 ÷ 建筑基底上限)
实际建筑基底 = 总建筑面积 ÷ 平均层数
停车位 = 向上取整(总建筑面积 ÷ 1000 × 千平方米停车指标)

总投资 =
  新增建筑面积 × 新建单价
  + 改造建筑面积 × 改造单价
  + 公共空间面积 × 公共空间单价
  + 其他费用
  + 预备费

资金缺口 = 总投资 - 直接收益
```

绿地与公共空间可能重叠，不能简单相加作为剩余用地扣减。

## 7. 成果一致性

- `scenario.json` 是指标与财务结果的机器可读主成果。
- `project_list.csv` 与 Excel 项目库保持项目数量和编码一致。
- `massing.geojson` 的各体块建筑面积之和与总建筑面积一致。
- `evidence.json` 是报告和 Excel 证据索引的来源。
- `quality_report.json` 是工作流是否可交付的闸门。
- `technical_review.json` 是最终技术签审和整改闭环的闸门。
- `visual_workplan.json` 是各小节图件、照片、资料缺口和质检状态的主清单。

## 8. 生产化扩展

后续建议按优先级扩展：

1. 建立人工复核界面，将候选条目升级为正式规则版本。
2. 增加文件效力、发布日期、失效日期、地域和更新类型字段。
3. 接入真实测绘 GeoJSON、现状建筑与公共设施 POI。
4. 增加 CRS 检测、地形高程、道路生成和地块切割。
5. 将财务模型扩展到征拆、土地、融资、税费和年度现金流。
6. 增加多情景比较、敏感性分析和审批留痕。
7. 数据量增大后接入向量数据库，并保留 SQLite 作为审计索引。
8. 安装QGIS桌面端后接入QGIS MCP，以实现图层、样式、处理算法、版式和SVG/矢量PDF导出的Agent控制；启用前必须通过连接诊断并限制任意PyQGIS代码执行风险。
9. 将第二章项目状态与图表清单接入统一任务看板，自动提示缺图、缺号、重复表号、过程性措辞和跨成果数值冲突。
