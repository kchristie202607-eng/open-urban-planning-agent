# 规划 PDF 离线 OCR 与引用状态管理

> **来源**：OUPAP 平台方法论文档 · 由私有知识库条目 `14-规划PDF_OCR识别与引用管理` 脱敏整理
> **适用场景**：规划文件（PDF）的本地离线识别、结构化输出、引用状态分级与专业核验
> **脱敏说明**：已移除本地脚本路径、内部工作流编号与具体项目验证记录

---

## 一、系统能力

配置 **Windows 本地离线中文 OCR**，无需安装额外软件，**不向外部平台上传规划文件**。引擎为 `Windows.Media.Ocr`，默认识别语言 `zh-Hans-CN`。

标准输出包括：

| 文件 | 内容 |
|---|---|
| `ocr.md` | 按 PDF 页码组织的原始识别文本 |
| `pages.jsonl` | 逐页结构化记录 |
| `manifest.json` | 源文件、页数、引擎、语言和生成时间 |

> 设计要点：**全链路本地化** —— 规划文件常含未公开内容，识别过程不得引入外部服务。

## 二、引用状态分级（核心）

OCR 结果**不得直接当作引用依据**。必须按下列状态逐级升格：

| 状态 | 含义 | 可否直接引用 |
|---|---|---|
| `OCR-RAW` | 机器原始识别 | **否** |
| `OCR-CLEAN` | 完成格式清理，未逐字核图 | **否** |
| `PAGE-VERIFIED` | 已与对应 PDF 页面逐字核验 | **可以** |
| `SOURCE-VERIFIED` | 已确认文件版本、发布机关和效力 | **可作为正式依据**，仍需按法定效力使用 |

> 铁律：**OCR、RAG、外部知识与模型记忆均不得替代法定原文。** 任何引用必须能回溯到原始文件与页码。

## 三、规划专业核验重点

下列字段**必须逐页核图**：

规划名称、发布机关、文号、日期、条款号、强制性用语、规划期限、面积、比例、人口、坐标、控制线、用地代码、指标、表格。

> OCR 无法保持表格结构时，应转为**人工录入 + 双人复核**，不得依赖自动解析结果。

## 四、流程要点

1. **识别与核验分离**：机器识别产出 `OCR-RAW`，人工核图后升格状态，两阶段不得合并。
2. **页码锚定**：所有结构化记录必须携带源文件名 + 页码，保证引用可回链。
3. **版本先判**：引用前先确认文件版本、发布机关与效力状态；同名多版须显式排除并留痕。
4. **不推测补全**：识别不清或缺失的内容保持为空并标注待核，严禁推测填充。
5. **离线优先**：先查本地已有识别结果，避免重复识别同一文件。
