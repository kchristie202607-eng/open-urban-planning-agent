# MapGIS 数据交付与 SQL 报错治理

> **来源**：OUPAP 平台方法论文档 · 由私有知识库条目 `66-数据交付MapGIS与SQL报错治理规则` 脱敏整理
> **适用场景**：把 CAD / GeoPackage / ArcGIS 数据交付给 MapGIS（K9 / 10.x / Desktop 九州 / 6.7）用户；或用户在 MapGIS 中执行查询报 SQL 语法错误
> **脱敏说明**：已移除项目名称、地名与源图文件名

---

## 一、硬前提：MapGIS 私有格式无法脱离 MapGIS 生成

MapGIS 原生数据格式（`.wt` 点 / `.wl` 线 / `.wp` 区 / `.wb` 工作区 / `.mpj` 工程 / `.hdf` 本地数据源）为**闭源二进制**，无公开写入库，**GDAL / OGR 无驱动**，FME 亦不支持。

> ⛔ **本机未装 MapGIS 时，不要尝试手写这些格式** —— 产物极可能损坏，且无法本地验证，属"假交付"。

**正确路径**：走 MapGIS 官方支持的**导入通道**，交付 Shapefile 或 DXF，由用户侧一并导入。

| MapGIS 版本 | 导入路径 |
|---|---|
| MapGIS 10 / Desktop 九州 | 数据目录 → 数据源 → 数据库右键「导入」→ 添加数据 → 选文件类型(shp/dxf) → 开始转换 |
| MapGIS 10.x（GDB 管理器） | 展开数据库 → 右键「简单要素类」→ 导入 → 其他数据 → 选 shp/dxf → 转换 |
| MapGIS 6.7 | 主菜单「文件转换」→ 装入 Shape/DXF → 保存文件为 wt/wl/wp → 保存工作区 → 输入编辑中加工程 |

MapGIS 10 **支持 shp 与 dxf/dwg 直接导入**（官方确认）。

## 二、`无效的 SQL 语法[near ".": syntax error]` 的根因与处置

### 2.1 机理

该报错串是 **SQLite 内核**的原文（`near "X": syntax error`）。MapGIS 本地数据源 / 查询层为 SQLite 内核，**拼 SQL 时把"数据源名 / 类名 / 字段名"直接拼进语句**，名字里出现下列字符即语法崩坏：

| 字符 | SQL 语义 | 报错形态 |
|---|---|---|
| `.` | 库名.表名 分隔符 | `near ".": syntax error` |
| `-` | 减号 | `near "-"` |
| `(` `)` | 函数括号 | 语法错乱 |
| 空格 | 标识符终止 | 名字截断 |
| 数字开头 | 数字字面量 | 非法标识符 |

### 2.2 典型反面样例

- 源 DWG 文件名含 **3 个点号 + 全角圆括号 + 连字符**（版本号与日期写法所致）
- CAD 图层名：数字开头 + 连字符（如 `9-乡镇国空-道路红线`）、纯连字符编码（如 `YD-100102`）、数字开头（如 `0-图框`）

### 2.3 定位验证法（不要凭猜）

对**不含任何特殊字符的图层**（如清洗后的 `开发边界_面`）执行同样查询：

- 能查 → 确认为命名问题，换清洗后数据即可
- 仍报错 → 是查询语句本身问题，索取 SQL 原文

### 2.4 命名清洗规则（交付前强制）

```
安全名 = 中文核心名 + "_" + 类型(面|线|注|点)
约束：仅汉字与下划线；剔除 . - ( ) （） 空格 等；不以数字开头；总长 ≤ 10
```

- **总长 ≤ 10** 同时满足 Shapefile 图层名与 MapGIS 字段长度限制
- **字段名一律 ASCII 化且 ≤ 10 字节**（如 `LU_CODE` 用地代码 / `LU_NAME` 用地名称 / `AREA_HA` 面积公顷）；中文 VALUES 可保留
- 重名冲突用数字后缀消歧，并提供「**图层对照表**」溯源

## 三、交付包标准结构

```
XX交付包_YYYYMMDD/
├── 00_必读_导入指引与报错说明.md     报错根因 + 三条导入路径 + 投影参数
├── 01_Shapefile/                     地理实体（UTF-8 + .cpg）★推荐
│   └── _图面附属/                     图框/图例/比例尺（提示用户不要勾选）
├── 02_Shapefile_GBK备用/             老版本 MapGIS 防乱码
├── 03_DXF/                           地理实体版 + 含图框图例版
├── 04_图层与字段对照表.xlsx          图层对照 / 字段对照 / 未输出清单 / 报错说明
└── 05_非空间属性表/                  无几何对象（ACAD_PROXY_ENTITY 等）转 CSV
```

## 四、实现踩坑清单（Python + geopandas + pyogrio + ezdxf）

1. **`shutil.rmtree(root)` 后必须 `os.makedirs(root)`**，否则 GDAL 报 `No such file or directory`（易误判为中文路径问题）。
2. **字段名必须先遍历全库建映射表**。中文字段名超 10 字节会被 DBF **截断在 UTF-8 字符中间**，读取时报 `UnicodeDecodeError: unexpected end of data`；须加兜底：非 ASCII 或 >10 字节者自动改名。
3. **图面附属必须"图层名 + 坐标簇"双条件拆分**。图例色块散落在业务图层内部（坐标近原点），只按图层名会漏、只按坐标会将整层误判。
4. **混在业务图层里的图例色块应直接剔除**，否则 `_图面附属/` 与主目录出现同名文件，用户极易导错。
5. **DXF 必有默认图层 `0`**（AutoCAD 强制保留），其上无实体；须在文档中说明"导入后可删空要素类"。
6. **对账必须闭合**：地理实体 + 图面附属 + 剔除项 = 源数据记录数，逐一核对。
7. 输出 Shapefile 用 `engine="pyogrio"`，UTF-8 需另写 `.cpg` 文件；GBK 版本供老版本使用。

## 五、铁律

- 未装 MapGIS 时**不得声称**已生成 MapGIS 原生文件；如实说明走导入通道。
- 面积等派生指标若与项目已知口径不符，**在交付文档中显著标注"须人工核验、不得直接引用"**。
- 原图例中无名称的代码、含义不明的图层，**保持原名留空，严禁推测填补**。
- 交付包必须附带生成脚本，保证可复跑与可追溯。
