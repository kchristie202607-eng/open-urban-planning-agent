# 控规政府汇报与成果组织标准

> **来源**：OUPAP 平台方法论文档 · 由私有知识库条目 `10-控规政府汇报与成果组织标准` 脱敏整理
> **适用场景**：控制性详细规划等规划成果的政府汇报材料组织与交付前检查
> **脱敏说明**：原文无项目数据，仅做体例统一

---

## 一、政府汇报的核心目标

**政府汇报不是说明书的压缩版，而是决策材料。** 每次汇报必须明确：

- 本次汇报要解决什么问题
- 推荐什么方案
- 为什么推荐
- 会影响哪些资源和部门
- 需要会议决定什么

## 二、推荐篇章结构

| 篇章 | 核心问题 | 推荐成果 |
|---|---|---|
| 1. 任务与审议事项 | 为什么编、范围多大、今天决定什么 | 范围图、任务卡、审议事项表 |
| 2. 上位传导与实施评估 | 哪些不能动、现行控规哪里不适应 | 传导矩阵、冲突叠加图、评估分区图 |
| 3. 核心问题 | 最关键的三至五项矛盾是什么 | 问题证据图、数据卡片、现场照片 |
| 4. 目标策略与方案比选 | 有哪些选择、利弊和代价是什么 | 方案对比图、比较表、推荐结论 |
| 5. 推荐空间方案 | 功能、用地和结构如何组织 | 结构图、用地布局图、重点地区图 |
| 6. 关键专项 | 交通、公服、绿地、市政、防灾能否支撑 | 专项总图、容量校核表、服务覆盖图 |
| 7. 规划控制 | 如何落实到单元和地块 | 单元图、控制指标图、图则示例 |
| 8. 实施安排 | 先做什么、谁负责、如何维护 | 近期项目图、时序表、动态维护机制 |

## 三、单页表达标准

每页原则上**只表达一个核心判断**，采用"**结论标题 + 证据图 + 关键数据 + 规划响应**"的组合。

- 标题应直接给出判断，避免仅写"现状分析""道路规划"等无结论标题。
- 图纸必须具备图名、图例、指北针、比例尺或示意说明、规划范围、来源和版本。
- 对比图使用**一致范围、底图和色彩口径**。
- 关键数字**不超过支撑本页结论所必需的数量**。

## 四、主汇报与备查材料分工

| 材料 | 内容 |
|---|---|
| **主汇报** | 核心问题、推荐方案、关键指标、实施路径和审议事项 |
| **备查材料** | 完整法规依据、原文摘录、测算过程、详细指标表、全部专项图、图则及意见回复 |

> 主汇报**不得因简化而改变技术结论**；备查材料应能回答结论来源和测算过程。

## 五、控规成果完整链条

正式成果应实现以下对应关系：

```
上位要求 → 现状证据 → 问题判断 → 规划策略 → 空间图纸
        → 控制指标 → 单元/地块图则 → 实施项目 → 数据库
```

> 任何关键结论若**无法沿此链条前后追溯**，应列为质量问题。

## 六、交付前检查

1. 审议事项是否清楚、可作出决定。
2. **原文引用和规划判断是否分开**。
3. 推荐方案是否说明备选方案及取舍。
4. 用地、人口、建筑量和设施容量是否守恒。
5. 总体、单元、街坊、地块控制是否闭合。
6. 图、文、表、指标、图则和数据库是否一致。
7. **刚性指标与弹性引导是否明确区分**。
8. 近期项目是否有空间落位、实施主体和时序。
9. **样本案例数据是否被误用为本项目依据**。
