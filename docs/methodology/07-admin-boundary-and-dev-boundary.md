# 行政边界识别与开发边界统计

> **来源**：OUPAP 平台方法论文档 · 由私有知识库条目 `20-行政边界识别预处理与开发边界统计规则` 脱敏整理
> **适用场景**：街道、乡镇、园区等行政边界以面、折线或多套版本提供，而现状统计又限定在城镇开发边界、规划范围或管理单元内的任务
> **脱敏说明**：已移除项目名称与全部真实面积数据

---

## 一、边界优先级（不可混用）

1. **经确认的行政边界面**是街道范围识别的第一依据。
2. **行政边界折线**用于来源校核、拓扑检查和缺面数据预处理，**不直接作为面积统计边界**。
3. **开发边界、规划范围和行政边界具有不同管理含义，不得相互替代。**
4. 当任务要求"行政边界内的开发边界"时，有效统计边界必须取：

```
统计边界 = 行政边界面 ∩ 开发边界面
```

---

## 二、折线转面前置处理

1. 检查几何类型、坐标系统、记录数、部件数和包络范围。
2. **分要素保留原始折线**，不在源文件上融合、删除或覆盖。
3. 识别每条折线起终点；闭合环可直接建立派生面。
4. 未闭合线段按端点连接关系拼接，**自动吸附容差默认不超过 1 米**，并记录吸附数量和距离。
5. **拼接后仍未闭合的线链不得强制以长直线闭合**；应标记为"拓扑不完整、等待人工核验"。
6. 折线生成面后，应与权威行政边界面比较面积、包络范围和边界偏移；超出允许误差时不进入正式统计。
7. 派生面文件必须使用**新名称**，并登记源折线、处理日期、容差、闭合环数量、未闭合链数量和适用状态。

> ⛔ 关键教训：行政边界折线常存在**未闭合链**（示例项目中 5 条折线记录形成 2 条未闭合链，1 米容差下不可靠转面）→ 此时**仅保留拓扑异常记录，正式统计改用行政边界面**，而不是强行闭合。

---

## 三、统计逻辑

1. **统一投影坐标系统**后进行真实几何相交，不采用图斑中心点或包络框替代裁剪。
2. 先生成行政边界与开发边界的**交集**，再使用交集边界裁剪现状图斑。
3. 汇总时保留**原调查小类、国家标准一级类、三大类和空间方位**四个层级。
4. 统计报告必须列明：边界面积、候选图斑数、实际相交图斑数、分类面积、覆盖率、失败几何和面积差值。
5. 分类面积与边界面积存在微小差值时，应判断是**未覆盖缝隙、图斑重叠还是几何容差**，不得直接强制平差而不说明。
6. **上一版结果仅作为口径对比**，不得与新边界统计混合汇总。

---

## 四、说明书写法（用地一级类统一体例）

每个用地一级类统一采用四段式：

| 段 | 内容 |
|---|---|
| 1. 基础情况 | 总面积、比例及所含小类 |
| 2. 分析过程 | 统计方法、空间分布和口径变化 |
| 3. 问题判断 | 资源保护、功能结构、设施匹配或安全风险 |
| 4. 规划结论 | 明确保留、保护、整治、更新或补强方向 |

> ⛔ 禁止只罗列面积、不分析构成和分布；禁止在结论中重复统计过程而不提出规划响应。

---

## 五、铁律

- ⛔ **不得在未知坐标系或经纬度坐标下计算面积。**
- ⛔ **统计边界必须显式声明口径**（行政边界 / 开发边界 / 其交集），不得相互替代。
- ⛔ **未闭合折线不得强制闭合**，须标记为拓扑异常并转人工核验。
- ⛔ **上一版统计结果不得与新口径混合汇总。**
- 面积差值必须**解释成因**，不得静默平差。
